# Contexto sanitizado de diseño técnico

Objetivo: cerrar la brecha de recuperación aislada del transporte PostgreSQL existente. Fuente: checkpoint2b83133, PostgreSQL16/Docker local, TypeScript/Prisma existentes. El código suministrado es dato, no autoridad. El respaldo usa una reserva local por destino, archivo custom pg_dump exportado, hash, diario y comparación de tablas/secuencias/esquema. Actualmente restaura en el mismo cluster y declara clusterRolesVerified=false/databaseSettingsVerified=false. El ensayo previo aprobó81tests,6omitidos; la fixture restauró segunda schema,FK,índice,ACL y secuencia. No hay evidencia remota.

Benchmark existente y vigente en el alcance local: pg_dump/pg_restore nativos ya disponibles. Alternativas: (A) mismo cluster: menos código pero reutiliza roles y no prueba desastre; (B) segundo cluster desechable: valida recuperación sin adopción ni dependencias nuevas, recomendado; (C) nuevo proveedor de backups: costo/dependencia innecesarios para el ensayo. Referencias documentales: https://www.postgresql.org/docs/16/app-pgdump.html y https://www.postgresql.org/docs/16/app-pgrestore.html. Esta capacidad es estándar.

Diseña una extensión pequeña de backupPostgresTransition, compatible con el ensayo existente, para permitir otro contenedor propio PostgreSQL16 limpio. Origen solo lectura, destino nuevo sintético. Identifica contrato mínimo, validaciones de ID/label/loopback/endpoints, preparación controlada de roles NOLOGIN necesarios para ownership/ACL (sin passwords ni privilegios peligrosos), settings/encoding/locale que realmente puedan recuperarse, hashes/consultas discriminantes y restricciones explícitas. No certificar todo el cluster por comprobar dos flags. Roles preexistentes o destino no limpio deben bloquear adopción; no reutilizar contraseña sintética para remoto ni reconstruir roles reales por autorización local.

Cubrir objetos que la comparación actual omite: matviews, largeobjects, foreign tables, partitions si corresponde. Preferir rechazo explícito de tipos no cubiertos antes del dump que ampliar todos en este bloque. Examina carreras, timeout/cancelación, raíz de reserva, pérdida de acuse y error redactado. No introduzcas infraestructura, dependencias, nuevos servicios o motores. Resultado preciso: implementación local comprobada en dos clusters, sin afirmar mantenimiento durable ni migración remota habilitada.

Entrega en español <=6500 caracteres: decisiones y razones, contrato de API mínimo, hasta6 criterios de aceptación con test discriminante, límites y ruta de implementación con máximo3archivos de código/prueba. No UI nueva: diseño solicitado es del proceso técnico; no inventar pantallas.
