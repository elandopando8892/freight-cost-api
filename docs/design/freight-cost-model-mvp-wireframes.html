Control de cotización

La cotización es el objeto principal: el usuario vuelve a una lista operativa y abre un panel de revisión sin cambiar de contexto.

Estado alterno de reapertura: si el folio ya no está disponible o no pertenece a la organización, se informa el motivo y se ofrece iniciar una cotización nueva; no se muestra un formulario vacío sin explicación.

Estado de carga: el encabezado, los modos Guiado/Rápido, el formulario y la revisión técnica conservan su estructura mientras se obtienen la cotización y las bases de costo.

Estado de permisos: un usuario VIEWER ve historial, detalle y linaje en modo solo lectura; calcular, guardar, confirmar y compartir requieren un rol operativo.

Estado de propuesta derivada: al volver a cotizar, el resultado identifica la cotización de origen y propone una etiqueta “Reapertura · …”; guardar crea un registro nuevo y deja intacto el original.

Estado comercial: el resultado concentra precio sugerido, margen, utilidad y decisión en un resumen interno; preparar o enviar al cliente sigue siendo una acción humana.

Quote Desk: la propuesta sigue el flujo Capturar → Revisar → Aprobar → Enviar manual; el último paso siempre requiere confirmación humana.

Preparar propuesta · acción humana

Incremento funcional de revisión: wireframe desktop/mobile y estados actualizados. El botón actual es “Revisar propuesta”; devuelve una vista previa sin guardar. Las pantallas de creación siguientes siguen siendo una propuesta futura.

La cotización confirmada se convierte en un borrador comercial sólo después de una revisión explícita. El panel muestra qué se copiará y qué información interna permanece fuera.

Regla de seguridad: no se muestran piso de costo, margen, base gobernada, supuestos ni evidencia técnica en este paso. “Preparar borrador” no aprueba ni envía correo.

Estado VIEWER: el mismo contenido se puede consultar, pero la acción queda deshabilitada con el motivo “Requiere un rol operativo”.

Estado de rechazo: si la fuente no está confirmada, no tiene snapshot o tiene decisión NO_GO, se conserva el detalle y se informa la razón; no se crea un borrador parcial.
